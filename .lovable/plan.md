## Add "Notifications" tab to WM Copilot

Add a third view mode alongside Dashboard / Client View in `BankwideWMCopilotView.tsx` (the `/bankdemo` WM Copilot tab) that mimics an advisor's daily signal-digest email.

### Changes

**1. `src/components/tepilot/insights/BankwideWMCopilotView.tsx`**
- Extend `ViewMode` to `"dashboard" | "client" | "notifications"`.
- Add a third toggle button labeled **Notifications** with a `Mail` icon next to the existing two.
- Render `<AdvisorNotificationsView clients={dashboardClients} onOpenClient={handleOpenClient} />` when active.

**2. New `src/components/tepilot/advisor-console/AdvisorNotificationsView.tsx`**
Email-client style layout:
- Top "inbox" header: sender = `Ventus AI Copilot <copilot@ventus.ai>`, recipient = `you`, today's date, subject = `Daily Signal Digest — {N} new triggers across your book`.
- Greeting paragraph: "Good morning, here's what I picked up across your {X} HNW clients overnight…"
- Grouped sections (collapsible cards) by signal severity / type, derived from `dashboardClients[*].detectedEvents`:
  - **High-priority life events** (e.g., liquidity event, business sale, inheritance)
  - **Opportunity triggers** (large deposits, new advisor-worthy spend patterns)
  - **At-risk signals** (outflows to competitors, disengagement)
- Each row: client name + initials avatar, one-line "what changed" summary, detected date, and two actions — **Open client** (calls `onOpenClient`) and **Prepare with Ventus** (calls existing `handlePrepareWithVentus` path).
- Footer signature block styled like an email sign-off ("— Ventus, your copilot").
- Pure presentation; reuses existing `DashboardClient` / `detectedEvents` data already generated by `generateDashboardClients(60)`. No new data sources, no backend calls.

### Out of scope
- No real email sending, no new edge functions, no schema changes.
- Styling stays within the strict light theme already used by WM Copilot.
