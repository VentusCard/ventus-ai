# FinovateFall mainstage script — 7-minute /bankdemo walkthrough

Deliver a stage-ready, timed script as a markdown document at `docs/finovate-fall-mainstage-script.md`. No app code changes.

## Structure (7:00 total, live-demo narration)

| Time | Beat | Screen |
|------|------|--------|
| 0:00-0:45 | Cold open: the problem — banks hold the richest behavioral data in a customer's life and still market like it's a mailing list | Title / Systems tab landing |
| 0:45-1:45 | **Systems** — the intelligence core: raw transactions in, five signal families out (Behavioral, Life Event, Financial, Demographic, Risk), plus external intelligence. Name the taxonomy depth without reading the list | Systems |
| 1:45-2:45 | **Intelligence Database** — the bank's own data, now queryable in plain language. Show a question, a cohort, and the fact every answer is evidence-backed | Intelligence Database |
| 2:45-3:45 | **AI Coworker** — signals become work. Live work stream, then one email brief: the moment, the evidence, the recommended action, the confidence | AI Coworker |
| 3:45-4:45 | **Automated Flows** — scale: 70+ product plays, each assembled from toggleable signals, audience math updating as signals flip on and off | Automated Flows |
| 4:45-6:15 | **Banking Personalization** — the payoff, one customer (Ricky) across three surfaces: Deals, Product, Relationship. Select once on the left, watch the signals drive three different generated experiences | 3 personalization tabs |
| 6:15-7:00 | Close: one intelligence layer, every channel; what it means for the customer and for the bank's growth | Wide shot / logo |

## Script content rules

- Written as spoken lines with stage directions in brackets, e.g. `[click Ricky in Customer Selection]`.
- Word budget calibrated to ~140 words/minute so the timings hold on stage.
- Behavioral, "vaguely specific" language — no exact transaction counts or dollar totals about a customer.
- Opportunity framing, never risk/stress language in customer-facing copy.
- No backend infrastructure or competitor names.
- Signals ordered the same way the Systems tab orders them, so the script matches what's on screen.

## Also included in the document

- A 30-second contingency version of each demo beat, in case a live generation is slow.
- A cut list showing what to drop first if running long.
- A one-line "landing sentence" per tab the presenter can fall back to.
