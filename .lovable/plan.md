

## Fix: Life Event Detection — Wrong Insights & Missing Event Diversity

### Problems Identified

1. **Broken regex mapping**: `mapEventNameToType("Family Trip to Tokyo")` matches `/family/` → returns `family_formation` → shows baby-related insights for a travel event. This is why Michael Thompson's Tokyo trip card says "preparing for a new arrival."

2. **Hardcoded insights are fragile**: The component maps AI-detected event names to 7 canned insight/step templates. Any event that doesn't cleanly match (like travel, career change, major purchase) falls through to the `retirement` default. The AI already generates contextual `talking_points` per event, but they're ignored.

3. **Only one event per customer**: The hook takes only `data.detected_events[0]`, discarding additional events the AI may detect. The user wants to "show different life events for different people."

### Fix (2 files)

**File 1: `src/components/demo/DemoLifeEventsView.tsx`**

- Remove `mapEventNameToType`, `INSIGHTS_BY_TYPE`, and `STEPS_BY_TYPE` entirely (the broken hardcoded system).
- Replace "Ventus AI Insights" section with the AI-returned `talking_points` from the edge function (already present on the `DetectedLifeEventResult` object but unused).
- Add a new "travel" category to the type system OR simply display the talking points as the insight content — no mapping needed.
- For "Recommended Next Steps," use the `talking_points` array (which the edge function generates as "3-5 natural conversation starters for advisor") styled as an ordered list.

**File 2: `src/hooks/useDemoEnrichment.ts`**

- Change `DetectedLifeEventResult` storage from a single event to an array: `detectedEventA: DetectedLifeEventResult[]` (take up to 2-3 events instead of just `[0]`).
- Update the state setters and the `DemoPage` props to pass arrays.
- Update `DemoLifeEventsView` to render multiple event cards per customer (showing the top 1-2 detected events).

### Result

- Michael Thompson's Tokyo trip will show travel-specific talking points generated by the AI, not baby content.
- Each customer will display their own unique detected events with contextually appropriate insights.
- No more reliance on fragile regex-to-hardcoded-text mapping.
