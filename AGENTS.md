# Project Architecture Decisions

- Deck-specific autonomous carousel behavior must be enabled through explicit props rather than inferred from presentation mode, so shared phone views remain unchanged outside the deck.
- The deck's raw rail overview derives representative examples and extracted fields from the existing Ricky fixture in a separate helper; beat 2.1 uses a bounded full-height accordion that opens fully collapsed so the presenter chooses what to reveal, with independently scrolling expanded content, while 2.2 shows profile facts above the raw ledger at the shared roller speed without KYC so other scenes retain their original behavior.
- Ricky's KYC accordion, profile headings, and explicit Section 4 customer-profile signal share structured deck-profile data; the story's profile detail branch stays separate from payment-rail grouping and transaction evidence so identity facts are never treated as inferred ledger signals.
- Deckmo slide state is authoritative and changes only through explicit arrow controls, its tested keyboard mapping, or deck-scoped benefit buttons resolving destinations by beat ID; never derive navigation from scrolling or embedded platform interactions, so platform exploration cannot accidentally advance the deck.
- The signal story is its own deck section after The Complete Picture with headings-only, internal, and external beats; hidden prose retains row geometry but is inaccessible and noninteractive on the opening beat, and insight-only entrances are gated by explicit scene activity and the internal beat so headings stay stationary and off-screen mounts cannot consume animations; content-sized grid rows share surplus height without DOM measurements, while other Ricky scenes remain unchanged.
- Signal story wording uses deck-scoped structured attribute and connector segments rendered as noninteractive child labels within one parent button; payment summaries use integer-cent calculations from the existing fixture so observed payments, estimates, and external context remain distinct.
- Deck cash-flow summaries use a separate integer-cent helper with explicit spending/transfer buckets, a bounded observation window, and explicit annualization at display boundaries; monthly residuals and illustrative external assets/profile balances stay separate so flow estimates cannot be confused with balances or verified valuations.
- Visibility and signal-story headers use separate structured copy, with story descriptions keyed to its reveal step, so the raw introduction cannot inherit complete-view claims.
- Section 4 supporting-transaction tables retain readable minimum column widths and scroll horizontally within screen-constrained pop-ups rather than truncating data, so original and enriched fields remain inspectable on smaller desktops.
