# Project Architecture Decisions

- Deck-specific autonomous carousel behavior must be enabled through explicit props rather than inferred from presentation mode, so shared phone views remain unchanged outside the deck.
- The deck's raw rail overview derives representative examples and extracted fields from the existing Ricky fixture in a separate helper; beat 2.1 uses a bounded full-height accordion with independently scrolling expanded content, while 2.2 shows profile facts above the raw ledger at the shared roller speed without KYC so other scenes retain their original behavior.
- Ricky's KYC block and profile heading share structured deck-profile data; keep KYC separate from payment-rail grouping and signal pillars to avoid treating identity fields as transactions or inferred signals.
- Deckmo slide state is authoritative and changes only through explicit arrow controls, its tested keyboard mapping, or deck-scoped benefit buttons resolving destinations by beat ID; never derive navigation from scrolling or embedded platform interactions, so platform exploration cannot accidentally advance the deck.
- The signal story is its own deck section after The Complete Picture with a two-step internal-then-external reveal; row entrances are gated by explicit scene activity and the internal beat so off-screen mounts cannot consume the animation and external reveals remain independent; deck-scoped content-sized grid rows share surplus available height while retaining inline narrative pills and evidence on demand; shared grid rows keep headers aligned without DOM measurements, while other Ricky scenes remain unchanged.
- Signal story wording uses deck-scoped structured attribute and connector segments rendered as noninteractive child labels within one parent button; payment summaries use integer-cent calculations from the existing fixture so observed payments, estimates, and external context remain distinct.
- Visibility and signal-story headers use separate structured copy, with story descriptions keyed to its reveal step, so the raw introduction cannot inherit complete-view claims.
